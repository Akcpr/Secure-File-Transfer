Authentication Flow — Register & Login

How users are created and verified, and how sessions are managed

Registration
Client generates (once)
RSA-2048 key pair
private_key.pem · public_key.pem
Username validation (local)
3–30 chars · alphanumeric only
→ server
Server checks
check_username → duplicate or available
Password validation (local)
≥7 chars · uppercase + lowercase + special
Password hashing (client-side)
SHA-256( password + salt + pepper )
salt = SHA-256(username)
pepper = PASSWORD_PEPPER env var
hash = SHA-256(password + salt + pepper)
→ server
Server stores in TinyDB
user_id (UUID) · username
password_hash · salt · role
public_key · created_at
Account created
Admin account (optional)
Client sends master password hash
Server compares to MASTER_HASH env var
Login & Session
User enters
username + password
Client hashes password
same formula as registration
→ server
Server looks up user
get_user(username) from TinyDB
Compare hashes
stored_hash == incoming_hash ?
MATCH
MISMATCH
Session created
token = UUID v4
expires in 24 hours
tied to socket fd
Rejected
"Invalid username
or password"
← client
Client receives
session token · role (user / admin)
Every subsequent command
1. get_session(socket_fd)
2. validate_session(token) — check expiry
3. get_user(username) — check role
4. execute or reject
